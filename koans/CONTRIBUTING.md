# Contributing to Thue++ Koans

Koans are small executable rewrite challenges. They are intentionally separate from ordinary examples and the general playground.

## Directory contract

```text
koans/
  <koan-slug>/
    readme.md
    tests/
      <name>.json
    hint.tpp
    solutions/
      YYYY-MM-DD-<solution-slug>.tpp
      YYYY-MM-DD-<solution-slug>.json
```

`readme.md` is the human/cultural artifact: front matter metadata, problem statement, monk wisdom, notes, and one generated leaderboard block.
`tests/*.json` are the behavior contract.
`hint.tpp` is an optional learner scaffold auto-loaded by the playground when the attempt editor is empty. It is a plain Thue++ program with comments and optional blanks/partial rules; it must not contain solution front matter, is not ranked, and should be treated as attempt text rather than a source file path.
`solutions/*.tpp` are dated submissions. Each solution must start with front matter containing human-facing `title`, title-slug `slug`, `author`, and `website`; optional `summary` describes the approach. The filename slug must match the front matter `slug`, and that slug must be the lowercase kebab-case title slug.
`solutions/*.json` files are generated by `tools/koan_generator.py`.

## Test manifest shape

Koan manifests use a top-level `cases` array. All IO assertions are resource-shaped.
Use normal `stdin`, `stdout`, and `stderr` resource names; `buffer` feeds an input resource and `expected_output` asserts an output resource.

```json
{
  "cases": [
    {
      "name": "basic",
      "resources": {
        "stdin": {
          "buffer": "input\n"
        },
        "stdout": {
          "expected_output": "expected\n"
        }
      },
      "exit_code": 0
    }
  ]
}
```

## One-file GitLab submission rule

For non-maintainer submissions, an MR may add exactly one file:

```text
koans/<koan-slug>/solutions/YYYY-MM-DD-<solution-slug>.tpp
```

The filename date records the submission day. The filename slug must match the solution front matter `slug`, and that slug must be the lowercase kebab-case form of the solution title. The MR must touch nothing else.
Maintainer-owned files include descriptions, tests, generated JSON, tooling, CI, and site code.

## Local verification

```bash
uv run python tools/koan_generator.py --check
uv run python tools/koan_generator.py --all
uv run python tools/koan_generator.py --missing
```

`--check` fails if any generated JSON or leaderboard block is stale.
`--all` regenerates only files under `koans/**`.
`--missing` reports koans with no qualifying ranked solution.

A ranked solution must pass every test case on the Go backend and achieve 100% rule coverage. There is no per-koan opt-out.

## Ranking

The main leaderboard sort is deterministic:

1. fewest rules;
2. fewest successful rewrite applications;
3. lowest peak state bytes;
4. lowest cumulative state bytes;
5. lowest total evals / rule checks;
6. lexical order by solution filename id.

The generator also records best-in-class winners for individual metrics in each solution JSON and renders a short records section in the leaderboard block.

## Safety

Do not run untrusted contributor solutions with write credentials. Read-only validation and trusted generation must stay separate.
